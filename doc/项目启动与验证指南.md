## 二、启动后端

打开一个终端，依次执行：

```bat
cd /d C:\workbuddy\新闻管理系统\java_news\server
set JAVA_HOME=D:\JDK\jdk-8u491-windows-x64\jdk1.8.0_491
D:\Maven\apache-maven-3.6.3-bin\apache-maven-3.6.3\bin\mvn.cmd spring-boot:run
```

看到日志里出现 `Started MyApp in x.xxx seconds` 就是启动成功了。

**已经打好包的话，也可以直接跑 jar（更快）：**

```bat
cd /d C:\workbuddy\新闻管理系统\java_news\server
D:\JDK\jdk-8u491-windows-x64\jdk1.8.0_491\bin\java.exe -jar target\study-0.0.1-SNAPSHOT.jar
```

**怎么判断后端正常？** 浏览器打开：

```
http://127.0.0.1:9100/api/classification/list
```

能看到 5 条分类的 JSON 就没问题。

## 五、常见问题

**Q1：首页图片全是裂图**
图片目录由 `application.yml` 里的 `BASE_LOCATION` 管理，现为相对路径 `.`
（2026-10-30 起已提交全部图片文件到仓库）。必须在 **`java_news` 仓库根目录**下启动后端，
相对路径才能解析到 `server/upload`；从其他目录启动就会全部 404。
另外检查是不是新上传的图片没被 git 提交（`git status` 看 `server/upload` 下有无未跟踪文件）。

**Q2：登录日志是空的**
这是原项目设定：`OpLogServiceImpl.getLoginLogList()` 里写死了只统计
`/api/user/userLogin` 这个地址，也就是**只记普通用户登录，不记管理员登录**。
要点：先用前台（`user1`）登录一次，登录日志才有数据。

**Q3：后台列表接口提示「无操作权限」**
说明 `ADMINTOKEN` 没了（比如浏览器清过缓存）。退回 `/adminLogin` 重新登录即可。

**Q4：9100 端口被占用**
说明后端已经在跑了，先关掉旧的那个窗口。

**Q5：启动日志里的端口不是 9100（变成一个高位端口，比如 64581）**
说明有「**环境变量**」把配置盖掉了。Spring Boot 读取配置的优先级是：

> **命令行参数 > 环境变量 > application.yml（配置文件）**

所以环境里如果存在 `SERVER_PORT`（或双下划线写法 `SERVER__PORT`）这类变量，
就会盖掉 yml 里写的 9100。

排查命令：

```bat
set | findstr /i "port spring"
```

如果确实有，启动时显式指定端口即可（命令行参数优先级最高，一定能盖过环境变量）：

```bat
D:\JDK\jdk-8u491-windows-x64\jdk1.8.0_491\bin\java.exe -jar target\study-0.0.1-SNAPSHOT.jar --server.port=9100
```

> 备注：这条是在自动化环境里实测时踩到的 —— 那个环境预置了 `SERVER__PORT`，
> 导致应用没绑到 9100。你自己的电脑上一般不会有这个变量，端口正常就忽略本条。
